pi-charter v2

Durable agent contracts inside pi-coding-agent — features carry their own validation, planning is the forcing function. design previewnot yet implemented

v2 collapses VAL-* criteria into per-feature checks, treats readiness/review/QA as first-class feature kinds, requires a planning forcing function (architecture pass → fan-out validation authoring → critic iterate-to-fixed-point), and adds an awaiting-clarification state so the agent can stall on user input without the Ralph loop spamming.

Superseded historical preview. This page shows the unreached v2 design (per-feature validation, a planning forcing function, an awaiting-clarification state, a feature DAG with plan.json/lock_plan). The shipped extension is now v3, which deliberately removed all of that: three tools (charter/charter_record/charter_status), a four-state FSM (active/paused/completed/abandoned), an Objective → Milestone → VAL register, and a charter that records evidence but never runs checks. For current behavior see CONTEXT.md and docs/implementation/. Kept only as a design-history artifact.

What changes in v2

Validation lives in features

No more charter.md Criteria section, no global VAL-* IDs. Each plan/<feature>.md carries its own ## Validation block split Happy / Edge. Lock-time gate: every feature needs ≥1 of each.

Four feature kinds

Readiness, Impl, Review, QA. Review and QA features are planner-authored alongside impl features. Milestones group impls + their gates; readyNext is feature-level so cross-milestone parallelism is normal.

Planning is the gate

Architecture artifact required → fan-out validation authoring per area → critic iterates to fixed point (cap 3) → readiness declared → QA briefs staged. lock_plan fails on any missing forcing function.

Typed evidence

Four evidence companions: command, review, qa, readiness. Subagents write JSON into the v2.1 dir-per-run layout work/<featureId>/evidence/<ts>/evidence.json plus companion files such as review.json, then call charter_record action=evidence evidenceFile=… themselves. Main agent stops re-typing subagent output.

Ask state

New status awaiting-clarification. charter_manage action=ask flips status with a one-line note; the question goes in chat. Ralph loop skips this status. Planning-only.

Config + BYOA

.pi/charter/charter-config.json selects persona implementations per role + model overrides. Default personas ship bundled with the extension; user can point any role at their own agent (resolution is pi-subagents' job).

Lifecycle

Ralph skip set in v2: paused, awaiting-clarification, completed, abandoned, budget_limited. Ask is planning-only; if active hits a real blocker the right move is pause, not ask.

Feature DAG — readiness, impl, review, QA

Historical note: auto-injection was removed in v2.2. Earlier previews had lock_plan synthesize review and QA gates, but v2.2 requires the planner or critic to author those features explicitly so the DAG has no ghost nodes.

Milestones are organizational + QA-bundling units, not execution barriers. readyNext is feature-level: cross-milestone parallelism is normal. Initial readyNext after lock = [r1, r2, r3] all parallel. Ralph's active prompt encourages parallel fixer dispatch when touches: don't overlap; planner-critic flags overlap during planning.

Per-feature validation

Inside plan/<feature>.md

---
id: m1-oauth-callback
milestone: m1-auth
order: 10
preconditions: [r1-creds, r3-skeleton]
touches: [app/auth/callback/**]
review: required
---

# OAuth callback handler

Implements the GET /auth/callback route. Exchanges code for
tokens, sets session cookie, redirects to /dashboard.

## Validation

### Happy
- check: callback-sets-session-cookie
  command: bun run test:int -- auth/callback.happy
- check: callback-redirects-to-dashboard
  command: curl -s -o /dev/null -w "%{http_code}\n" \
    http://localhost:3000/auth/callback?code=valid \
    | grep -q 302

### Edge
- check: callback-rejects-expired-code
  command: bun run test:int -- auth/callback.expired
- check: callback-rejects-state-mismatch
  command: bun run test:int -- auth/callback.csrf

Lock-time shape gate

  • Every impl feature needs ≥1 Happy and ≥1 Edge check.
  • Check IDs are scoped: m1-oauth-callback.callback-sets-session-cookie. Globally unique by construction.
  • Command and verifier annotations are descriptive; agents run checks and record evidence.
  • charter-planner-critic grades validation depth per feature — returns structured validation-underspecified: [feature-id] when checks read like "we tested it" rather than enumerated failure modes.
  • Underspecified iterations loop with the explorers; cap at 3 rounds, then escalate to awaiting-clarification with a one-line note.

No more VAL-*

Charter.md drops the entire Criteria section. criterion-state.json is removed. feature-state.json is single source of truth and nests per-check status under each feature.

Evidence annotations

Command

Describes a useful command for the agent to run. Charter stores the recorded command output; it does not execute the command.

Hook / service

Describes evidence another integration or service can provide.

Manual / review

Human, root-agent, or user-owned subagent evidence with rationale and artifacts.

Annotations describe what good evidence looks like; recorded evidence decides completion.

Planning — forcing functions

Lock fails on: missing architecture.md, any blocking readiness item, any feature without Happy+Edge checks, any unanswered clarification entry. Planning is fully reversible — the repo is never written during planning or lock. The first repo writes happen in active phase (impl features producing code).

Subagent-authored typed evidence

Main agent stops re-typing subagent output into charter_record fields. Subagent writes the JSON and records it. Evidence uses the v2.1 dir-per-run layout: work/<featureId>/evidence/<ts>/evidence.json with optional companions like qa.md, review.json, and artifacts. Main's post-spawn job collapses to: read prose summary for working memory → call charter_status → pick next move. Same-feature races are last-write-wins on idempotent updates.

Personas

pi-charter ships zero bundled personas. Users bring their own review or QA subagents when useful, and record their output as evidence.

## Commands

Declared in charter.md

Commands are a simple key-value block that status output and delegated personas can quote verbatim. Use stable names so feature validation does not duplicate long shell pipelines.

## Commands

build: bun run build
test:  bun test
dev:   bun run dev

Worked example — feature smoke

A planner can reference the shared keys while keeping feature validation readable:

  • build proves the package compiles: charter run build.
  • test runs the default suite before evidence is recorded.
  • dev starts the local surface for QA or manual probes.

charter-config.json

Schema

{
  "personas": {
    "planner-critic": { "agent": "charter-planner-critic" },
    "reviewer":       { "agent": "charter-reviewer",
                        "model": "claude-sonnet-4-20250514" },
    "qa":             { "agent": "my-team-qa-agent" },
    "readiness":      { "agent": "charter-readiness-probe" }
  },
  "qaDir": "docs/qa",
  "policy": "interactive",
  "criticIterationCap": 3
}

Resolution

  • Location: .pi/charter/charter-config.json in cwd. Per-repo. Same pattern as pi-reminders / pi-dag-tasks.
  • Persona agent name defaults to the bundled charter-* implementation. User overrides by pointing agent at any name the pi-subagents extension knows.
  • Model override beats the agent's frontmatter model when present.
  • policy: "interactive" (default) allows charter_manage action=ask. "autonomous" forbids it — agent must self-resolve via subagent research or defer to ## Open Questions at completion.
  • qaDir repointable for teams with existing docs conventions; default docs/qa.
  • BYOA contract is pi-subagents' surface: user's named agent must accept the documented task-prompt schema and produce the documented typed evidence shape.

Ralph reprompt loop (unchanged from current v1.5)

Trigger + gating

Single SUBAGENT_ALL_IDLE_EVENT from pi-subagents fires when root + every async child are idle. Debounced 10s, send-time gates (ctx.isIdle(), !hasPendingMessages(), liveAsync.size===0), 30s min interval between fires. Stale-ctx handlers wrapped in try/catch.

Skip set in v2: paused, awaiting-clarification, completed, abandoned, budget_limited.

Prompt selection

buildRalphPromptForCharter() reads bound charter's status and picks: planning, active, paused. New awaiting-clarification case is in the skip set — no reprompt because the agent is blocked on chat, not on idle time.

Delivered as custom message type charter-ralph-continue with bordered renderer; visible in scrollback by default.

Storage layout

<projectDir>/

│   │   └── charter-config.json         # personas, qaDir, policy
│   └── charters/<charterId>/

│       ├── feature-state.json          # per-feature + per-check status
│       ├── state.json                  # lifecycle, sessionId reverse, clarification note
│       ├── plan.json                   # locked plan snapshot

│       ├── library/
│       │   └── architecture.md         # plan-time only · frozen at lock
│       ├── qa/<surface>.md             # qa briefs (charter-scoped in v1)
│       └── work/<featureId>/evidence/<ts>/

│           └── review.json / qa.json / command.json / artifacts...
│

v1 → v2 deltas: no criterion-state.json; no separate Criteria section in charter.md; new library/architecture.md; new qa/<surface>.md staging; evidence files use the v2.1 dir-per-run layout and are now typed JSON authored by subagents.

Tools — v2 surface

toolactionsv2 notes
charter_manage create · pause · resume · complete · force_complete · amend_charter · ask ask flips status to awaiting-clarification; optional one-line note; chat carries the question. Planning-only. Forbidden under policy: autonomous.
charter_plan view · add_feature · update_feature · lock_plan shape gate at lock: ≥1 Happy + ≥1 Edge per impl feature; review/qa features are planner-authored; readiness + architecture + qa briefs required; unanswered clarifications block lock.
charter_record evidence · verify · handoff_apply new evidenceFile: <path> param imports typed JSON and validates against kind-specific schema; inline params still work for main-agent-authored evidence.
charter_status read-only returns drift views computed from feature-state.json: readyNext, blockingForComplete, per-feature check rollups, clarification note when present.

Invariants

  • Source of truth is markdown. Mutable status never lands in charter.md or plan/*.md frontmatter.
  • Planning never writes to the repo. First repo writes happen in active phase when impl features land code. QA briefs stay in charter dir until proven useful (no auto-promotion in v1).
  • Atomic writes for every sidecar: write temp, fsync, rename.
  • Agent is the loop driver. No auto-spawn scheduler; Ralph steers only the same session that owns the charter.
  • Evidence required before complete. Subagents author typed JSON; main agent does not re-type.
  • Tactical todos stay in pi-dag-tasks. Charters are macro contracts.
  • Architecture frozen at lock. Mutation only allowed during amend_charter.
  • Critic iterates to fixed point with hard cap 3 before escalating to clarification.

What's left to decide

  • v1-of-v2 scope: typed evidence + per-feature validation + critic mandate + readiness + config + ask state; defer milestone-driven fan-out + architecture-required-always; tunable.
  • One charter or several to implement the rewrite itself (self-hosting). Probable split: breaking-change bundle + persona/critic bundle.
  • Review-skip threshold: hard cap (e.g. 50%) + per-skip critic judgment, or pure judgment?
  • Architecture artifact mandate: every charter, or only ≥3-feature charters?
  • Resume after clarification: reuse resume, or a dedicated clarified action? Auto-flip on user reply requires chat-layer hook.
